# 02. 通信プロトコルと監視

## メッセージ
転送は SignalR + MessagePack。定義は `src/Ip.Shared/Protocol/Messages.cs` にあります。

| 向き | メッセージ | 内容 | 送信タイミング |
| --- | --- | --- | --- |
| 下り | `VoltageCommand` | `CommandId`, `Seq`, 電圧 [V], `BasedOnMs` (根拠にした計測時刻) | 帰還を受信して制御計算した直後 |
| 下り | `AbortCommand` | `CommandId` | 停止・異常時。プラントは電圧を 0 にする |
| 上り | `EncoderFeedback` | `Seq`, `CommandId`, 計測時刻, 台車パルス, 振子パルス, E2E 遅延, ドライブ有効, `Epoch` | 帰還周期ごと (1〜100ms) |
| 上り | `MotionEvent` | `ESTOP` / `LIMIT` / `CMD_TIMEOUT` / `DRIVE_DISABLED` + パルス | 即時 (通信遅延は受ける) |

帰還が**生の物理量ではなくエンコーダのパルス数**なのは実機と同じです。
量子化された整数から位置を復元し、速度は差分 + LPF で推定します
(`src/Ip.Shared/Control/VelocityEstimator.cs`)。

### 指令の破棄規則
プラント側 (`VirtualPlant`) は次の指令を捨てます。

- `CommandId` が現行より**古い**指令 — 前回の運転セッション宛ての指令
- `Seq` が**逆行した**指令 — 追い越しや再送で順序が崩れた指令

ドライブ無効中に新しい `CommandId` が来た場合は、そのセッションごと拒否し
`DRIVE_DISABLED` を通知します。この挙動が [保護の多重化](#保護の多重化) の要になります。

### `Epoch`
プラントのリセット世代。世代が変わったらコントローラは速度推定器と積分状態を初期化します。
これがないと、リセット直後にリセット前のパルス差分が速度として推定され、
いきなり大きな指令が出ます。

## 時刻の扱い
**制御の判断に 2 台の時計の差を持ち込まない**、が本プロジェクトの原則です。

| 量 | 使う時計 | 理由 |
| --- | --- | --- |
| 開始時刻の判定 | プラント時計のみ | 時計ズレで運転開始が揺れないため |
| 速度推定の Δt | プラント時計のみ | 差分が時計ズレで歪むと速度が飛ぶため |
| E2E 遅延 (`受信時刻 - BasedOnMs`) | プラント時計のみ | 同じ時計の差なので、サーバとブラウザの時計ズレの影響を受けない |
| 「上り遅延」の**表示** | 両方 (クロック同期で補正) | 2 台の時計をまたぐため。表示専用で制御には使わない |

クロック同期 (`src/Ip.Shared/Protocol/ClockSynchronizer.cs`) は NTP 方式です。
往復時間からオフセットを推定しますが、その結果は UI 表示にしか流れません。

## 受信値の矯正
受信した `double` は範囲チェックの前に**必ず有限性を検査**します
(`Sanitize.Finite`)。

`Math.Clamp` は Infinity を境界へ落としますが **NaN は素通しします**。
NaN が 1 つ混ざると以降の比較がすべて false になり、
「ウォッチドッグが永久に鳴らない」「同じ値かの判定が常に不成立になる」という
**静かな故障**を生みます。検証は `tests/Ip.Shared.Tests/SanitizationTests.cs`。

## 保護の多重化
保護はバックエンドとプラントの 2 層に分かれており、**層をまたいで依存しません**。

| 層 | 検知するもの | 守るもの |
| --- | --- | --- |
| バックエンド (コントローラ) | 転倒 (\|θ\|)、ソフトリミット (\|x\|)、ウォッチドッグ (`max(300ms, 3×帰還周期)`)、旧セッションのイベント破棄 | 制御ロジックの前提が崩れたことの検知 |
| プラント (ドライブ) | 非常停止、メカリミット、指令タイムアウト 500ms、無効中の指令拒否 | 通信もバックエンドも死んだときに電圧を出し続けないこと |

### 復帰手順が 1 段階では済まない理由
バックエンド側の「異常リセット」だけでは復帰しません。
プラント側のドライブが無効のままなので、次の開始指令は `DRIVE_DISABLED` で拒否され、
バックエンドは再び FAULT に落ちます。
**現場側の復帰操作 (「プラント初期化」) が要る**という実機の手順をそのまま再現しています。

これは不便ではなく仕様です。遠隔側の操作だけで動力が復帰してしまう設計は、
現場に人がいる状態で危険だからです。
検証は `tests/Ip.Shared.Tests/PlantProtectionTests.cs` と
`tests/Ip.Shared.Tests/SafetyIntegrationTests.cs`、および `e2e/tests/safety.spec.ts`。

## 通信路のエミュレーション
`src/Ip.Shared/Simulation/DelayLine.cs` は**送信側のキュー**として実装しています。

SignalR は TCP 上で動くのでパケットは落ちません。
現実のパケットロスは、アプリから見ると**再送による遅延スパイク**として現れます。
そのため損失は「+150ms の注入」と「追い越し禁止」で模擬しています。

| パラメータ | 模擬するもの |
| --- | --- |
| 一定遅延 | 伝搬遅延 |
| ジッタ | キューイング遅延の揺らぎ |
| 再送スパイク | パケットロス後の TCP 再送 |
