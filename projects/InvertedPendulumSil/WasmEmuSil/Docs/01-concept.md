# 01. 目的と位置づけ

## 一言で
**部品 (WASM) を取り寄せてクライアント側で組み立てる、決定的な倒立振子エミュレータ。**
制御プログラムは仮想 MCU に外から注入し、Visual Studio や LLDB でデバッグできる。

## 答えようとしている問い
NetworkedSil は「安定化ループをバックエンドに置けるか」を問い、
「LAN 内の長い振子でぎりぎり。実機は階層型にすべき」と答えました。
WasmEmuSil はその階層型を前提に、次の問いに答えます。

1. **実機に載せるファームウェアを、実機なしでどこまで開発・検証できるか。**
   組み込みの制御プログラムを HAL だけに依存する形で書き、
   PC 上の仮想 MCU で同じソースを走らせてデバッグする。
2. **エミュレータ環境そのものを配布物として管理できるか。**
   プラント・ドライバ・エンコーダといった部品を WASM にして、
   構成情報 (manifest) と一緒にサーバから配る。クライアントは組み立てるだけ。
3. **部品や制御プログラムに OS の資源 (TCP・ファイル) を安全に開放できるか。**
   サンドボックスを既定とし、必要な capability だけを宣言・承認・同意の 3 段で通す。

## 設計原則
それぞれ「守らないと何が起きるか」とセットで書きます。

### 仮想時間で決定的に回す
スケジューラは固定ステップの仮想時間を進めるだけで、壁時計を制御判断に使いません。
実時間へのペーシングは「仮想時間が壁時計より先に進まないよう待つ」だけの外付けです。

守らないと: デバッガで止めた瞬間にウォッチドッグが鳴り、再開後の挙動が壊れます。
テストの再現性も失われます。NetworkedSil の既知の制約 (タイマ粒度・時間スリップ) はこれで消えます。

### 部品は互いを知らない
部品は入力ポートを読み、出力ポートを書くだけです。他の部品を呼びません。
配線はエンジンが manifest に従って行います。

守らないと: 部品の組合せが manifest で表現できなくなり、「配信して組み立てる」が成り立ちません。

### ファームウェアは HAL だけに依存する
ファームウェアは `abi/ip_hal.h` (WIT では `ip:emu/hal`) の関数しか呼びません。
同じソースを wasm32 (配布) とネイティブ共有ライブラリ (デバッグ) にビルドします。

守らないと: デバッグした物と配った物が別物になります。
HAL は実機 MCU の BSP でも実装できる粒度にしておき、実機移植の経路を残します。

### 既定はサンドボックス、例外は 3 段で通す
部品とファームウェアには既定で WASI の時計・乱数・ファイル・ソケットを与えません。
必要なら manifest に capability を宣言し、サーバの管理者が承認して署名し、
クライアントの利用者が初回に同意します。実施は Wasmtime の WASI preview 2 の capability で行います。

守らないと: 配信サーバが乗っ取られるとクライアントで任意の I/O が走ります。
宣言のない I/O は WASI の import が存在しないので実体化の時点で失敗します。

### 実行コードは検証してから動かす
manifest は Ed25519 で署名し、各アーティファクトは sha256 で照合し、
WASM は Wasmtime でコンパイルして WIT のワールド (import / export) を manifest と突き合わせてから実体化します。
この検証コードはサーバとクライアントで**同じクレート** (`ipemu-core`) を使います。

守らないと: サーバで通った構成がクライアントで落ちる、あるいはその逆が起きます。

### 検証は Rust の中で閉じる
物理モデルは `ip-model` クレートに 1 か所だけ書き、部品とテストの両方から使います。
正しさは外部の基準値ではなく**性質** (エネルギー保存・平衡・対称性・RK4 の次数・Riccati 残差) で検証します
([09-verification.md](09-verification.md))。

守らないと: CI に別言語のツールチェーンが要り、基準値の更新が属人的になります。

## スコープ外 (今回は作らない)
- 命令セットレベルの CPU エミュレーション (Cortex-M の実バイナリ実行)。
  仮想 MCU は「HAL 付きの関数呼び出しモデル」です。
  ただし `cpu-virtual` を別の CPU 部品に差し替えられる構造にはしておきます。
- 多軸・多リンクへの次元拡張 (NetworkedSil で検討のうえ却下済み)。
- 複数クライアント間の連携 (1 クライアント = 1 エミュレータ環境)。
- クライアント本体 (シェル / エンジン) の自己更新。部品・UI・ファームウェアは配信で更新できるが、本体はインストーラで更新する。
