台車型倒立振子 SIL シミュレータ

プラント(台車・振子・モータ)は Worker 上で 1ms 固定ステップ、コントローラ(バックエンド相当)は別 Worker で動き、両者は遅延を注入した通信路だけでつながっています。全制御をバック側で行う純 SIL 構成で、通信遅延が倒立維持に与える影響を観察できます。

前回の搬送機シミュレータの原則「バックは自分の指令が実行された前提で動かない」はそのまま維持しています。変わったのは、指令が位置決め1回ではなく帰還1回ごとの電圧指令になり、制御ループ全体が通信路をまたいだ点です。

遅延余裕 — 純 SIL が成立する条件

倒立点の不安定極 λ は振子が短いほど大きくなり、許容できるループ遅延はおおむね 1/λ のオーダーに縮みます。バック側は帰還周期・速度推定フィルタ・任意遅延を含めた線形閉ループを 1ms 刻みで模擬し、発散しない最大遅延を二分探索して「理論遅延余裕」として表示します。

振子長不安定極周期 1ms5ms20ms50ms100ms
0.3 m7.5 rad/s58 ms57 ms52 ms41 ms35 ms
0.6 m5.3 rad/s86 ms85 ms80 ms68 ms59 ms
1.0 m4.1 rad/s110 ms109 ms105 ms95 ms86 ms

Node 上の実時間結合テスト (振子長 0.6m、周期 5ms、外乱あり) では、往復約 70ms まで倒立を維持し、約 90ms で転倒しました。理論値 85ms と整合しています。予測器を有効にすると往復約 140ms でも維持できました。

この表が示すとおり、前回設計の「帰還 100ms 固定」は、長い振子なら LAN 内でぎりぎり成立します。一方で、短い振子やインターネット越しの SignalR では余裕を超えます。実機へ移行する際は、安定化ループをドライブ(組み込み側)に置き、バックは目標値とモード管理に専念する階層型に切り替えるべきです。このシミュレータは、その判断を数値で裏付けるための実験台という位置づけです。

通信路エミュレーション

  • SignalR は WebSocket (TCP) 上で動くため、パケットは欠落せず順序も保たれます。損失は再送による遅延スパイクとして現れるので、「スパイク率」で +150ms の遅延を注入し、追い越しは禁止しています。
  • 遅延は送信側の Worker 内で、計測時刻を基準にしたキューとして実装しています。プラントは 1ms ステップをまとめて進めるため、計測時刻は送信処理の時刻ではなく積分ステップの時刻を使います。

このモックの実行基盤と制約

  • Worker は Blob URL から起動します。ホスト側の CSP で拒否された場合は、同じ関数をメインスレッドで動かすフォールバックに切り替え、右上のバッジに表示します。
  • SharedArrayBuffer は cross-origin isolation (COOP/COEP) が有効なときだけ使い、それ以外は postMessage で状態を受け渡します。
  • setTimeout の最小間隔 (約4ms) の制約により、E2E遅延には数ms の下限があります。
  • 物理モデルは実時間に同期させています。そのため積分刻みは決定的ですが、通信タイミングは実行ごとに揺らぎます。
    • 実時間同期 (現行): 人が触って観察できる。一方で、同じ条件でも結果が完全には再現しない
    • ロックステップ同期: プラントがバック応答を待って進むので再現性は完全になる。一方で、遅延の効果を仮想時間で模擬する必要があり、UIでの即時操作とは相性が悪い

Blazor WASM へ移植する際の注意

  • マルチスレッド (WasmEnableThreads) には COOP/COEP ヘッダが必要です。Blazor Web 構成では ServeMultithreadingHeaders オプションで配信できます。
  • [JSImport]/[JSExport] は少なくとも導入時点ではメインスレッド専用でした。描画側との境界はメインスレッドに置き、Worker との共有は SharedArrayBuffer に限定します。
  • .NET 10 のマルチスレッド WASM で System.Threading.Timer が runtime 内部で落ちる報告があります。固定ステップループは Timer に依存させず、Stopwatch 基準で自前で回します。
  • 物理モデル・LQR設計・遅延余裕計算は共有クラスライブラリに置きます。そうすれば、このモックで Node を使って行ったような結合テストを xUnit でそのまま書けます。

おすすめの実験手順

  • 「倒立から開始」で倒立させ、通信遅延を少しずつ上げながら外乱を加え、遅延予算バーが縦線を越えるあたりで倒れることを確かめる
  • 予測器を有効にして同じ遅延で倒れにくくなることを確かめ、次にジッタを増やして予測がずれる様子を見る
  • 振子長を 0.3m にして、理論遅延余裕が縮むことを確かめる
  • 「前回設計」プリセットで 100ms 周期でも倒立する条件と、振子長を短くしたときに崩れる条件を比べる
  • 非常停止のあと「異常リセット」(バック側の確認)だけ行って開始すると、プラントが DRIVE_DISABLED で拒否し、バックが再び FAULT に落ちることを確かめる。「プラント初期化」(現場側の復帰)で再開できる
